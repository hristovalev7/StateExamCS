## Основни системни примитиви

Управлението на процеси в Unix стъпва на няколко системни извиквания: `fork()` (създаване), `exec()` (зареждане на програма), `exit()` (завършване) и `wait()`/`waitpid()` (синхронизация). Ядрото поддържа за всеки процес контролен блок (PCB / task_struct) с PID, състояние, регистри, таблица на файловите дескриптори, UID/GID, адресно пространство и т.н.

## Създаване на процес — fork()

```c
pid_t pid = fork();
```

`fork()` създава **почти точно копие** на викащия процес. Връща се **два пъти**:
- в родителя → PID на детето (>0)
- в детето → 0
- при грешка → -1

Детето наследява копие на адресното пространство (на практика **copy-on-write**), отворените файлови дескриптори, UID/GID, текущата директория. Различават се: PID, PPID, времената за CPU се нулират, ключалки не се наследяват.

## Изпълнение на програма — exec()

Семейство функции (`execl`, `execv`, `execlp`, `execvp`, `execve`...). `execve()` е същинското системно извикване — останалите са обвивки.

```c
execlp("ls", "ls", "-l", NULL);
```

`exec` **заменя** текущия образ на процеса с нова програма: ново код/данни/стек, но **същият PID** и обикновено същите отворени дескриптори. При успех **не се връща** (старият код вече не съществува); връща -1 само при грешка.

Класическата идиома е **fork + exec**: родителят прави `fork()`, детето прави `exec()`, така стартира нова програма като отделен процес (точно това прави shell-ът).

## Завършване на процес — exit()

```c
exit(status);      // библиотечна, изпълнява atexit, flush на буфери
_exit(status);     // системна, директно прекратява
```

Връща се код за изход (0–255, ниските 8 бита). Ресурсите се освобождават, но записът в таблицата на процесите остава докато родителят не го прочете → **zombie (зомби)** процес. Ако родителят завърши преди детето, детето се осиновява от `init`/`systemd` (PID 1), който прибира статуса.

## Синхронизация със завършването на сина — wait()

```c
pid_t pid = wait(&status);              // чака произволно дете
pid_t pid = waitpid(child, &status, 0); // чака конкретно / с опции (WNOHANG)
```

Родителят се блокира докато дете завърши, прибира exit-статуса и така **изчиства зомбито**. Макроси за анализ: `WIFEXITED(status)`, `WEXITSTATUS(status)`, `WIFSIGNALED(status)`, `WTERMSIG(status)`. Алтернатива — обработка на сигнала `SIGCHLD`, който ядрото изпраща на родителя при завършване на дете.

## Права на процеси — потребителски идентификатори

Всеки процес носи идентификатори:
- **RUID / RGID** (real) — кой реално е стартирал процеса.
- **EUID / EGID** (effective) — използват се при **проверка на правата** за достъп до файлове и ресурси.
- **SUID / SGID** (saved set-user/group-ID) — запазват предишен EUID, за да може процесът да го възстанови.

При обикновен `exec` идентификаторите се запазват. Но ако изпълнимият файл има вдигнат бит **set-UID (SUID)**, EUID става равен на собственика на файла (затова `passwd` може да пише в `/etc/shadow` като root). Смяна: `setuid()`, `seteuid()`, `setreuid()`. UID 0 = root (привилегирован).

## Механизми за междупроцесни комуникации (IPC) — обзор

Понеже процесите имат отделни адресни пространства, нужни са специални механизми за обмен:
- **Сигнали** — асинхронни известия.
- **Канали (pipes / FIFO)** — поток от байтове.
- **System V / POSIX IPC** — обща памет, семафори, опашки от съобщения.
- Допълнително: сокети, mmap, файлови ключалки.

## Сигнали

Сигналът е **асинхронно известие** за събитие (софтуерно прекъсване). Примери: `SIGINT` (Ctrl+C), `SIGKILL` (9, неуловим), `SIGTERM` (15), `SIGSEGV`, `SIGCHLD`, `SIGUSR1/2`.

Изпращане: `kill(pid, sig)`, `raise(sig)`, `alarm()`. Обработка — три варианта: подразбиращо действие, игнориране (`SIG_IGN`) или собствен обработчик:

```c
signal(SIGINT, handler);          // стар интерфейс
sigaction(SIGINT, &act, NULL);    // препоръчителен, по-надежден
```

`SIGKILL` и `SIGSTOP` **не могат** да се прихващат или игнорират. Маскиране/блокиране: `sigprocmask()`, набори `sigset_t`. Сигналите носят малко информация (по същество само номера) → груб, но бърз механизъм.

## Програмни канали (pipes)

Еднопосочен байтов поток между процеси.

```c
int fd[2];
pipe(fd);          // fd[0] = четене, fd[1] = запис
```

Обикновено: `pipe()` → `fork()` → всеки затваря ненужния си край → обмен. Използва се за **роднински** процеси (наследяват дескрипторите). Това е механизмът зад shell pipe-а `ls | grep x`.

**FIFO (named pipe)** — `mkfifo("path", mode)` — има име във файловата система, така че го ползват и **неродствени** процеси. Семантика: четенето блокира при празен канал, записът — при пълен буфер; запис в канал без читатели → `SIGPIPE`.

## POSIX IPC пакет

Три именувани обекта с имена от вида `/name`; компилиране често с `-lrt` (и `-pthread` за семафорите).

**Обща памет (shared memory)** — най-бързият IPC, защото няма копиране през ядрото:
```c
int fd = shm_open("/seg", O_CREAT|O_RDWR, 0666);
ftruncate(fd, size);
void *p = mmap(NULL, size, PROT_READ|PROT_WRITE, MAP_SHARED, fd, 0);
```
Няколко процеса проектират един и същ сегмент в адресните си пространства и четат/пишат директно. Понеже няма вградена синхронизация, **трябва** да се пази със семафори/мютекси. Премахване: `shm_unlink()`.

**Семафори** — броячи за синхронизация и взаимно изключване:
```c
sem_t *s = sem_open("/sem", O_CREAT, 0666, 1);
sem_wait(s);   // P — намалява; блокира при 0
// критична секция
sem_post(s);   // V — увеличава
```
Именувани (`sem_open`, между процеси) и неименувани (`sem_init` в обща памет). Решават класическата задача за критична секция / producer-consumer.

**Опашки от съобщения (message queues)** — обмен на дискретни **съобщения** (не поток), с приоритети:
```c
mqd_t q = mq_open("/q", O_CREAT|O_RDWR, 0666, &attr);
mq_send(q, buf, len, prio);
mq_receive(q, buf, maxlen, &prio);
```
Ядрото пази съобщенията подредени по приоритет; `mq_receive` връща първо най-приоритетното. Премахване: `mq_unlink()`.

---

Кратко сравнение за финал: **сигналите** са за известия, **каналите** — за байтов поток между (предимно) роднински процеси, **обща памет** — за бърз обмен на големи данни (но иска ръчна синхронизация), **семафори** — за синхронизация, **опашки от съобщения** — за структуриран обмен с приоритети. Има и стар **System V IPC** аналог (`shmget`, `semget`, `msgget` с ключове `key_t` и `ftok`), който е по-старият вариант на същите три механизма.
