# 19. Функционално програмиране

## 1. Обща характеристика на функционалния стил

### Характерни особености

Функционалното програмиране стъпва върху **λ-смятането** на Church (1936) — формализъм,
изчислително еквивалентен на машините на Тюринг. Затова λ-смятането е за функционалния
стил това, което машината на Тюринг е за императивния.

Основни идеи:

- **Изчислението е оценяване на изрази**, а не изпълнение на команди. Програмата не описва
  *как* стъпка по стъпка да се промени паметта, а *какво* е резултатът.
- **Функциите са пълноправни стойности** (first-class): могат да се подават като аргументи,
  да се връщат като резултат и да се свързват с имена — точно като числата.
- **Прозрачност по означение**: при липса на странични ефекти изразът винаги дава една и съща
  оценка и може да се замества със стойността си.
- **Рекурсия** вместо цикли; **неизменими** стойности.

Накратко, във ФП има функции с параметри (**абстракция**), които се **прилагат** над аргументи
(**апликация**), могат да са други функции (**функции от висок ред**) и да се дефинират чрез
себе си (**рекурсия**).

Функционалните езици се класифицират по:
- типова система — динамично (стойностите имат тип, *Scheme*) или статично (променливите имат
  тип, *Haskell*);
- странични ефекти — нечисти (*Scheme*) или чисти (*Haskell*);
- стратегия за оценяване — стриктно (*Scheme*) или лениво (*Haskell*).

### Основни компоненти

Всеки изразен език се описва с три неща (Абелсон–Сасман):

1. **Примитивни изрази** — най-простите градивни единици.
2. **Средства за комбиниране** — как от прости изрази строим сложни.
3. **Средства за абстракция** — как именуваме съставни обекти и боравим с тях като с цяло.

**Примитивни изрази.** Литерали (числа, булеви константи, знаци, низове) и символи (имена).
Оценката на литерал е самият той, а на символ — стойността, свързана с него:

```scheme
5        ; -> 5
#t       ; -> #t
+        ; -> #<procedure:+>
a        ; -> Грешка! (несвързан символ)
```

**Средства за комбиниране.** Основната конструкция е **комбинацията** — прилагане на функция
над аргументи: `(<израз0> <израз1> ... <изразn>)`.

**Средства за абстракция.** `define` (именуване) и дефиниране на функции (`lambda`).

### Оценяване на израз

**Основно правило за оценяване на комбинация:** оценяват се всички подизрази, после операторът
(функция) се прилага над оценките на аргументите.

```scheme
(+ (* 2 3) (- 10 4))   ; -> (+ 6 6) -> 12
```

Има изключения от това правило — **специални форми**. При тях не всички аргументи се оценяват
или редът е друг. Такива са `define`, `if`, `cond`, `quote`, `lambda`, `and`, `or`.

```scheme
(if (< 3 5) (+ 7 3) (/ 1 0))   ; -> 10  (вторият клон не се оценява)
(define x 2.5)                 ; свързва x, не оценява "комбинация"
'(+ 2 3)                       ; -> (+ 2 3)  (quote не оценява)
```

### Дефиниране на функция и оценяване на приложение

`(define (<функция> <параметри>) <тяло>)` свързва име с функция, която при подадени стойности
на параметрите пресмята тялото.

Приложението на функция се обяснява със **заместителния модел**: в тялото на функцията всеки
параметър се замества със съответния аргумент.

```scheme
(define (square x) (* x x))
(define (f x y) (+ (square (1+ x)) (square y) 5))

(f 2 4)
; (+ (square (1+ 2)) (square 4) 5)
; (+ (square 3)      (square 4) 5)
; (+ (* 3 3)         (* 4 4)    5)
; (+ 9 16 5) -> 30
```

### Модели на оценяване

Въпросът е **в какъв ред** прилагаме заместването. Чисто изразено в λ-смятане, правилото е
`(λx.E1)(E2) ↦ E1[x := E2]`.

**Апликативно (стриктно, „лакомо“, call-by-value).** Първо се оценяват аргументите, после се
заместват. Оценява се „отвътре навън“. Това прави *Scheme*.

```scheme
(square (+ 1 2))
; (square 3)     ; първо оценяваме аргумента
; (* 3 3) -> 9
```

**Нормално (лениво, call-by-name).** Аргументите се заместват *неоценени* и се пресмятат чак
когато потрябват. Оценява се „отвън навътре“.

```scheme
(square (+ 1 2))
; (* (+ 1 2) (+ 1 2))   ; заместваме неоценен израз
; (* 3 3) -> 9
```

Двете дават еднакъв резултат тук, но се различават по две важни неща:

- **Завършване.** Нормалното оценяване може да даде резултат там, където апликативното зацикля
  или гърми:
  ```scheme
  (define (const x y) x)
  (const 5 (loop))   ; loop не завършва
  ```
  Апликативно: оценяваме `(loop)` → не завършва. Нормално: `(const 5 (loop)) -> 5`, защото
  `y` никога не се оценява.
  **Теорема за нормализация (Curry):** ако *някоя* стратегия достига резултат, то и нормалната
  го достига (и до същия резултат). Следствие: ако нормалната даде грешка/не завърши, никоя
  друга няма да успее.

- **Ефективност.** Чистото call-by-name преоценява един и същ израз многократно (виж как
  `(+ 1 2)` се появи два пъти горе). Затова *Haskell* използва **call-by-need**: аргументът се
  оценява най-много веднъж, а резултатът се споделя.

Накратко: *Scheme* е апликативен, *Haskell* — ленив. Лениво оценяване позволява и **безкрайни
структури** (`[1..]`), защото се смята само толкова, колкото потрябва.

## 2. Функции от по-висок ред

**Функция от по-висок ред** е функция, която приема функция като аргумент и/или връща функция
като резултат. Възможна е, понеже функциите са пълноправни стойности.

### Функции като параметри

Изнасяме *общата схема* в една функция, а конкретното действие подаваме като параметър.
Класически пример е дясното свиване `foldr`:

```scheme
(define (foldr op nv l)
  (if (null? l) nv
      (op (car l) (foldr op nv (cdr l)))))

(foldr + 0 '(1 2 3))   ; -> 6
(foldr * 1 '(1 2 3))   ; -> 6
```

Аналогично `map` (прилага функция върху всеки елемент) и `filter` (избира по предикат):

```scheme
(map  square '(1 2 3))   ; -> (1 4 9)
(filter odd? '(1 2 3 4)) ; -> (1 3)
```

В Haskell тези функции имат тип, който ясно показва, че приемат функция:

```haskell
map    :: (a -> b)      -> [a] -> [b]
filter :: (a -> Bool)   -> [a] -> [a]
foldr  :: (a -> b -> b) -> b   -> [a] -> b

map (+1) [1,2,3]   -- [2,3,4]
filter even [1..5] -- [2,4]
foldr (+) 0 [1,2,3]-- 6
```

### Функции като резултат (затваряния)

Функция може да **върне** функция. Върнатата функция запомня средата, в която е създадена
(**затваряне**), затова „вижда“ стойностите от обхвата си:

```scheme
(define (adder n) (lambda (x) (+ x n)))
(define inc (adder 1))
(inc 7)   ; -> 8   (n остава свързано с 1)

(define (compose f g) (lambda (x) (f (g x))))
((compose square inc) 3)  ; -> 16
```

Идеята е свързана с **къриране**: функция на повече аргументи може да се разглежда като функция
на един аргумент, връщаща функция на останалите. В Haskell това е вградено:

```haskell
f x y = ...     -- е същото като
f = \x -> \y -> ...
-- затова  (+) 3  е функция, която прибавя 3
map ((+) 3) [1,2,3]  -- [4,5,6]
```

### Анонимни (ламбда) функции

Често функцията-параметър ни трябва само на едно място — тогава я строим „на място“, без име,
с `lambda`:

```scheme
(lambda (<параметри>) <тяло>)

((lambda (x) (+ x 3)) 5)      ; -> 8
(map (lambda (x) (* x x)) '(1 2 3))  ; -> (1 4 9)
```

Всяка функция е именувана ламбда — двете дефиниции са еквивалентни:

```scheme
(define (g x) (* x x))
(define g (lambda (x) (* x x)))
```

В Haskell синтаксисът е `\<параметри> -> <тяло>`:

```haskell
(\x -> 2*x + 1) 3            -- 7
map (\x -> x*x) [1,2,3]      -- [1,4,9]
(\f x -> f (f x)) (*3) 4     -- 36
```

Анонимните функции правят функциите от по-висок ред удобни за писане: подаваме точно нужното
поведение направо като аргумент, без излишно именуване.
