# Задача 2 - Държавен изпит 12.09.2024

## Условие

### 1) Разгледайте дадената по-долу програма. В полето за отговор напишете какво ще изведе тя.

```cpp
class A {
public:
    A() { prn('c'); }
    ~A() { prn('d'); }
    virtual void prn(char ch) const {
        std::cout << 'A' << ch << ';';
    }
};

class B : public A {
public:
    B() { prn('c'); }
    ~B() { prn('d'); }
    virtual void prn(char ch) const {
        std::cout << 'B' << ch << ';';
    }
};

int main() {
    A* obj = new B;
    obj->prn('p');
    delete obj;
}
```

**Отговор:** `Ac;Bc;Bp;Ad;`

**Обяснение:**
- Създава се обект от тип `B`, достъпен чрез указател към `A`
- При конструкция на `B`:
  - Първо се извиква конструктор на базовия клас `A`: 
    - В него се вика `prn('c')`
    - **ВАЖНО:** По време на конструкция виртуалните функции НЕ работат полиморфно! Обектът още не е напълно `B`, само частта `A` е конструирана
    - Извиква се версията от `A` → `Ac;`
  - След това се извиква конструктор на `B`: 
    - В него се вика `prn('c')`
    - Сега обектът е `B`, но виртуалните функции в конструктори пак не работят полиморфно
    - Извиква се версията от `B` → `Bc;`
- Извикване на `obj->prn('p')`: обектът е напълно конструиран, виртуално извикване работи → `Bp;`
- При `delete obj`:
  - Деструкторът на `A` НЕ е виртуален, затова се извиква само той (не се извиква деструктора на `B`)
  - В деструктора на `A`: `prn('d')` → `Ad;`
  - Деструкторът на `B` НЕ се извиква - това е грешка в кода (undefined behavior)

**Важно:** В този код има сериозен проблем - деструкторът на `A` трябва да е `virtual`, за да се извика правилно деструкторът на `B`. Поради липсата на виртуален деструктор имаме memory leak и undefined behavior.

### 2) Срещу всяко от твърденията напишете „Да", ако то е вярно, или „Не", ако е невярно.

| Твърдение | Отговор |
|-----------|---------|
| А) Конструкторът на един клас може да бъде статичен. | **Не** |
| Б) Деструкторът на един клас може да бъде статичен. | **Не** |
| В) В статична член-функция на даден клас можем да достъпваме както статичните, така и нестатичните член-променливи на класа. | **Не** |
| Г) В статична член-функция на даден клас можем да направим обръщение към виртуална член-функция на същия клас без да има създаден обект. | **Не** |
| Д) Във виртуална функция на даден клас можем да направим обръщение към статична член-функция на същия клас. | **Да** |
| Е) Ако в един абстрактен клас има член-функция, тя задължително трябва да бъде виртуална. | **Не** |

**Обяснения:**
- **А)** Конструкторите не могат да бъдат статични, защото те създават конкретни обекти
- **Б)** Деструкторите не могат да бъдат статични, защото се извикват за конкретни обекти
- **В)** Статичните функции нямат достъп до нестатични член-променливи (няма `this` указател)
- **Г)** Статичните функции не могат да извикват виртуални функции без обект
- **Д)** Виртуалните функции могат да извикват статични функции (не зависи от полиморфизъм)
- **Е)** Абстрактните класове могат да имат и невиртуални функции

#### Решение:

```cpp
class Item {
    std::string m_label;
public:
    Item(std::string t) : m_label(t) {}
    
    virtual ~Item() {}
    
    const std::string& label() const {
        return m_label;
    }
};

template <typename T>
class Box : public Item{
    T* m_contents;
public:
    Box(std::string label, const T& contents)
        : Item(label)
    {
        m_contents = new T(contents);
    }
    
    Box(const Box&) = delete;
    Box& operator=(const Box&) = delete;
    virtual ~Box() { delete m_contents; }
    T& contents() { return *m_contents; }
};

Box<int>* createRandomIntBox() {
    int randomValue = rand() % 100 + 1;
    return new Box<int>("random box", randomValue);
}

Box<int>* toIntBox(Item* p) {
    return dynamic_cast<Box<int>*>(p);
}

int main() {
    Item* p = createRandomIntBox();
    toIntBox(p)->contents() = 42;
    std::cout << "Box {"
              << "\n Label: " << p->label()
              << "\n Contents: "
              << toIntBox(p)->contents()
              << "\n}\n";
    delete p;
}
```

#### Отговори за празните места:

1. **Ред 6:** `virtual` - деструкторът трябва да е виртуален, за да се извика правилно при delete през базов указател
2. **Ред 13:** `template` - класът `Box` е шаблонен клас
3. **Ред 15:** `T*` - съдържанието се пази като указател към тип T
4. **Ред 18:** `label` - предаваме параметъра на конструктора на базовия клас
5. **Ред 20:** `contents` - копираме съдържанието
6. **Ред 25:** `virtual` - деструкторът трябва да е виртуален (или може да се остави празно, ако деструкторът на Item е virtual)
7. **Ред 26:** `*m_contents` - връщаме дереференцирания указател
8. **Ред 31:** `new Box<int>` - създаваме нов Box обект
