# Задача 2 - Държавен изпит 09.07.2024 (C++)

Задачата да се реши на езика C++.

## Даден код:

```cpp
class Base {
public:
    ~Base() {}
    virtual Base& self() { return *this; }
};
class Derived : virtual public Base {
    int ptr;
public:
    Derived() { delete[] ptr; }
    ~Derived() { delete[] ptr; }
    Derived& self() { return *this; }
};
int main() {
    Base* b = new Derived();
    delete b;
}
```

---

## 1) Разгледайте дадения по-долу фрагмент. След това отговорете на въпросите, които следват.

### А) Класът Base е абстрактен, защото в него има виртуални функции.

**Отговор: Не**

**Обяснение:** Класът е абстрактен само ако има поне една **чисто виртуална** функция (pure virtual), т.е. `virtual тип функция() = 0;`. Класът Base има виртуална функция `self()`, но тя не е чисто виртуална, защото има имплементация. Следователно Base не е абстрактен клас и може да бъде инстанциран.

### Б) Класът Base е полиморфен, защото в него има виртуални функции.

**Отговор: Да**

**Обяснение:** Класът е **полиморфен**, ако има поне една виртуална функция. Виртуалните функции позволяват dynamic dispatch (динамично свързване) - правилната функция се избира по време на изпълнение според реалния тип на обекта, а не според типа на указателя. Base има виртуална функция `self()`, следователно е полиморфен клас.

### В) Функцията Base::self е чисто виртуална (pure virtual).

**Отговор: Не**

**Обяснение:** Чисто виртуална функция се дефинира с `= 0` в края: `virtual Base& self() = 0;`. Функцията `Base::self()` има имплементация `{ return *this; }`, следователно е обикновена виртуална функция, не чисто виртуална.

### Г) Функцията Derived::self е public, защото в Base::self е public.

**Отговор: Не**

**Обяснение:** В C++ **виртуалните функции не наследяват автоматично нивото на достъп**. Derived::self е public, защото е декларирана в public секцията на класа Derived, а не защото Base::self е public. Ако Derived::self беше декларирана в private: секция, тя щеше да бъде private, независимо че Base::self е public.

### Д) Base::self връща референция (reference) към временен обект

**Отговор: Не**

**Обяснение:** `*this` не е временен обект, а **референция към текущия обект** (обектът, за който е извикана функцията). Временни обекти са тези, които се създават и унищожават веднага (напр. резултати от изрази). `*this` сочи към обекта, който съществува, докато съществува неговата област на видимост. Връщането на `*this` е валидна и често използвана практика (напр. за method chaining).

### Е) В Base::self има грешка, защото връща указател, а типът ѝ е референция към Base&.

**Отговор: Не**

**Обяснение:** Няма грешка. Функцията е декларирана да връща `Base&` (референция към Base) и връща `*this`, което е от тип `Base&`. `*this` е дереференцирането на this указателя, което дава референция към текущия обект. Типовете съвпадат перфектно.

## 2) По-долу са описани няколко наблюдения от по-горния фрагмент. Срещу всяко от тях напишете „Грешка", ако е описан проблем в кода или „ОК", ако описва валидна конструкция.

### А) Функцията на Base не е виртуална, съдържа виртуална функция и наследяваща му клас динамични ресурси.

**Отговор: Грешка**

**Обяснение:** Деструкторът на Base (`~Base()`) **не е виртуален**, а трябва да бъде! Когато имаме полиморфна йерархия (виртуални функции) и унищожаваме обект на производен клас чрез указател към базов клас (`Base* b = new Derived(); delete b;`), **ако деструкторът не е виртуален, извиква се само деструкторът на базовия клас**, а не на производния. Това води до:

- Memory leak (паметта на Derived не се освобождава правилно)
- Undefined behavior
- Ресурсите в Derived не се освобождават

**Правилно:** `virtual ~Base() {}`

### Б) Деструкторът на Base е публичен.

**Отговор: OK**

**Обяснение:** Това твърдение е **OK**.

### В) self е дефинирана като виртуална в Base, но не е и в Derived.

**Отговор: OK**

**Обяснение:** Когато виртуална функция се override-ва (предефинира) в производен клас, **не е задължително** да се пише отново ключовата дума `virtual`. След като функцията е виртуална в базовия клас, тя остава виртуална във всички производни класове автоматично. В C++11 и по-нови версии е препоръчително да се използва `override` за яснота: `Derived& self() override { return *this; }`, но това не е задължително.

### Г) Типът на Base::self е Base, но Derived::self има тип Derived.

**Отговор: OK**

**Обяснение:** Това е валидна употреба на **covariant return types** (ковариантни върнати типове). При override на виртуална функция, производният клас може да върне указател или референция към **по-специализиран тип** (производен клас) от върнатия тип в базовия клас:

- Base::self() връща `Base&`
- Derived::self() връща `Derived&`

Това е валидно, защото Derived наследява Base, и `Derived&` може да се конвертира към `Base&`. C++ позволява това за да улесни работата с полиморфни йерархии.

## 3) Разгледайте дадения по-долу фрагмент.

```cpp
virtual class Foo {
public:
    virtual Foo() {}
    virtual ~Foo() {}
    virtual int var;
    int func(virtual int param) {
        return param;
    }
    virtual void anotherFunc() {
        virtual int localVar;
    }
};
class Bar : virtual public Foo { };
```

На кой редове записаната дума virtual е намерена правилна използование според правилата на C++? За всеки ред отговорете "Да" или "Не".

| Ред    | Място                                       | Отговор | Обяснение                                                                                               |
| ------ | ------------------------------------------- | ------- | ------------------------------------------------------------------------------------------------------- |
| ред 1  | дефиниция на клас                           | **Не**  | `virtual` не може да се използва пред `class` при дефиниция на клас. Класовете не са виртуални.         |
| ред 3  | дефиниция на конструктор                    | **Не**  | Конструкторите **не могат** да бъдат виртуални. Обектът се създава с точно определен тип.               |
| ред 4  | дефиниция на деструктор                     | **Да**  | Деструкторите **могат и трябва** да бъдат виртуални в полиморфни класове.                               |
| ред 5  | дефиниция на член-променлива                | **Не**  | Член-променливите не могат да бъдат виртуални. Само функции могат да бъдат виртуални.                   |
| ред 6  | дефиниция на параметър на функция           | **Не**  | Параметрите на функции не могат да бъдат виртуални. `virtual` се отнася само за функции.                |
| ред 9  | дефиниция на член-функция                   | **Да**  | Член-функциите могат да бъдат виртуални. Това е основната употреба на `virtual`.                        |
| ред 10 | дефиниция на локална променлива във функция | **Не**  | Локалните променливи не могат да бъдат виртуални.                                                       |
| ред 14 | наследяване на клас                         | **Да**  | `virtual public` е **виртуално наследяване**, което решава diamond problem при множествено наследяване. |

**Обобщение на правилната употреба на `virtual`:**

- ✅ Деструктори
- ✅ Член-функции
- ✅ Наследяване (`virtual public/protected/private`)
- ❌ Конструктори
- ❌ Член-променливи
- ❌ Параметри на функции
- ❌ Локални променливи
- ❌ Дефиниция на клас

## 4) Допълнете програмата на подчертаните места, така че да изведа текст "ABC" на екрана.

```cpp
// Обърнете внимание, че функциите
// не приемат аргументи!
class A {
public:
    A() { std::cout << '__'; }
    __________ void f() { std::cout << '__'; }
};
class B : public A {
public:
    B() { std::cout << '__'; }
};
int main() {
    _____ obj;
    _____::f();
}
```

### Решение:

```cpp
class A {
public:
    A() { std::cout << 'A'; }
    static void f() { std::cout << 'C'; }
};
class B : public A {
public:
    B() { std::cout << 'B'; }
};
int main() {
    B obj;
    A::f();
}
```

### Обяснение:

**Ред на изпълнение:**

1. **`B obj;`** - Създава обект от тип B
   - Първо се извиква конструкторът на базовия клас A
   - `A()` печата **'A'**
   - След това се извиква конструкторът на B
   - `B()` печата **'B'**
   - До тук имаме: **AB**

2. **`A::f();`** - Извиква статична функция f() от клас A
   - `f()` е `static`, защото се извиква без обект (`A::f()`, а не `obj.f()`)
   - Функцията печата **'C'**
   - Общ изход: **ABC**

**Защо `static`?**

- Функцията се извиква без обект: `A::f();`
- Статичните функции принадлежат на класа, не на обект
- Не изискват инстанция на класа
- Извикват се чрез оператора за scope resolution `::`

**Алтернативен подход (без static):**
Ако искахме функцията да не е static, трябваше да я извикаме чрез обект:

```cpp
obj.f(); // или A::f(); ако f() е static
```

## Резюме на ключови концепции:

1. **Абстрактен клас**: Има поне една чисто виртуална функция (`= 0`)
2. **Полиморфен клас**: Има поне една виртуална функция
3. **Виртуален деструктор**: Задължителен в полиморфни класове с наследници
4. **Covariant return types**: Производният клас може да върне по-специализиран тип
5. **Виртуално наследяване**: `virtual public Base` - за решаване на diamond problem
6. **Статични функции**: Извикват се без обект, чрез `::`
